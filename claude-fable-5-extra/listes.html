🧠 Data structures

Le guide interactif pour comprendre — et pas juste réciter — les array, linked list, stack, queue, tree et hash table. Manipule chaque structure, puis teste-toi avec le quiz. Vocabulaire technique en anglais, pour coller au jour de ton entretien.

Pourquoi ces structures tombent à tous les entretiens ?

Parce que choisir la bonne structure, c'est 80 % de la performance d'un programme. L'intervieweur ne veut pas des définitions par cœur : il veut voir que tu sais quand utiliser quoi, et pourquoi. Chaque section ci-dessous te laisse manipuler la structure pour que ça devienne un réflexe.

🎯 Les 5 réflexes qui font bonne impression en entretien

  • Annonce spontanément la complexity de ta solution (« ici c'est O(n) parce que… »).
  • LIFO → stack, FIFO → queue : nomme le principe avant la structure.
  • Array = access O(1) mais insertion/deletion au milieu O(n) — cite toujours le compromis.
  • « Il faut que ce soit rapide » → pense hash map en premier.
  • BST degenerate = O(n) → mentionner les balanced trees (AVL, red-black) marque des points.

🧮 L'array

La structure la plus fondamentale : des cases contiguës en mémoire, indexées à partir de 0. C'est la brique de base de presque tout le reste.

🎮 Manipule-le

Essaie « Access » avec un index, puis « Search » avec une value : compare la différence de vitesse.

💡 Comment ça marche ?

Les éléments sont stockés côte à côte en mémoire. L'adresse de arr[i] se calcule en une seule opération (start + i × taille) : l'access est instantané. En revanche, insert ou delete au milieu oblige à shift tous les éléments suivants.

  • Contiguïté mémoire = très cache-friendly : parcourir un array est ultra rapide.
  • Les dynamic arrays (JS Array, Python list, Java ArrayList) se redimensionnent seuls : push en O(1) amorti.

⏱️ Complexity

Access par indexO(1)
SearchO(n) — O(log n) si sorted (binary search)
Insert / delete en finO(1) amorti
Insert / delete au milieuO(n)

💼 Là où tu le croises en vrai

🖥️ Interfaces & listesLe feed d'une app, les rows d'un tableau UI : il y a un array derrière chaque .map() React.
🖼️ Images & sonUne image est un array de pixels, un son un array de samples.
📦 Buffers & données brutesLecture de fichiers, network packets, ArrayBuffer.
🧱 Base des autres structuresStacks, queues, heaps et hash tables sont souvent construits sur un array.
🎯 En entretien : annonce toujours le compromis « access O(1) mais insertion/deletion O(n) ». Si l'exercice fait beaucoup d'insertions en head, propose une linked list ou une deque. Et si l'array est sorted, pense binary search O(log n).

🔗 La linked list

Des nodes éparpillés en mémoire, reliés par des pointers : chaque node connaît sa value et l'adresse du next.

🎮 Manipule-la

Compare « Add au head » (instantané) et « Add au tail » (il faut traverse toute la list).

💡 Comment ça marche ?

Pas d'index : pour atteindre le 5e élément, on suit les flèches depuis head. En échange, insert ou remove au head ne coûte qu'un changement de pointer — aucun shift.

  • La version doubly linked ajoute un pointer prev pour circuler dans les deux sens.
  • Avec un pointer tail conservé, l'add au tail redevient O(1).

⏱️ Complexity

Access au i-ème élémentO(n)
SearchO(n)
Insert / delete au headO(1)
Insert au tailO(n) — O(1) avec pointer tail

💼 Là où tu la croises en vrai

↩️ Undo / redo & historiqueChaque state pointe vers le previous et le next : doubly linked list.
⚡ Cache LRUHash map + doubly linked list : l'implémentation classique (et une question d'entretien culte).
🎵 Playlists & carrouselsMorceau next / previous = suivre un pointer.
🧠 Memory allocatorsLes blocs libres du heap sont chaînés entre eux (free list).
🎯 En entretien : trois grands classiques à maîtriser — detect un cycle avec Floyd (fast & slow pointers), reverse une list en place, trouver le middle avec deux pointers.

🥞 Le stack — LIFO

Dernier arrivé, premier sorti. On n'interagit qu'avec le top : push pour poser, pop pour reprendre. Comme une pile d'assiettes.

🎮 Manipule-le

Lance la démo « call stack » pour voir ce que fait le moteur JavaScript à chaque appel de fonction.

💡 Comment ça marche ?

Impossible de retirer l'assiette du bas sans tout enlever. Deux opérations O(1) suffisent (push / pop), souvent implémentées sur un simple array. Si on push sans limite… stack overflow 💥 (oui, comme le site).

⏱️ Complexity

PushO(1)
PopO(1)
Peek (lire le top)O(1)
SearchO(n) — mais on ne le fait jamais

💼 Là où tu la croises en vrai

📞 Le call stackChaque fonction appelée est pushed ; une récursion infinie = stack overflow.
↩️ Undo / redoCtrl+Z pop le dernier changement (deux stacks pour gérer le redo).
🌐 Bouton retourLe ← du navigateur pop l'historique des pages visitées.
🧩 Parsing & compilersParenthèses équilibrées, évaluation d'expressions, DFS traversal.
🎯 En entretien : dès que l'énoncé implique de « revenir en arrière » ou de traiter le plus récent d'abord → stack. Exos stars : valid parentheses, min stack, évaluation d'expression postfixée.

🚶 La queue — FIFO

Premier arrivé, premier servi. On entre par le back (enqueue), on sort par le front (dequeue) — comme une file d'attente à la boulangerie.

🎮 Manipule-la

Ajoute quelques éléments puis dequeue : le premier entré sort toujours en premier.

💡 Comment ça marche ?

enqueue ajoute au back, dequeue retire au front, les deux en O(1). Deux variantes à citer :

  • La deque : entrée et sortie des deux côtés.
  • La priority queue : le plus urgent sort d'abord — implémentée avec un heap, opérations en O(log n).

⏱️ Complexity

EnqueueO(1)
DequeueO(1)
Front (lire la tête)O(1)
Priority queue (heap)O(log n)

💼 Là où tu la croises en vrai

📨 Message queuesRabbitMQ, Kafka, SQS… les tâches attendent leur tour entre services.
🔁 Event loop JavaScriptLes callbacks patientent dans une queue avant d'être exécutés.
🗺️ BFSExplorer un graph niveau par niveau — le shortest path non pondéré.
📺 Buffering & streamingVidéo, frappes clavier, imprimante : absorber les pics de débit.
🎯 En entretien : BFS = queue, DFS = stack — dis-le explicitement, c'est souvent LE point attendu. Et cite la priority queue (heap) pour les task schedulers.

🌳 Le binary search tree (BST)

Tout ce qui est plus petit part à left, tout ce qui est plus grand part à right. Résultat : chercher, c'est éliminer la moitié des candidats à chaque étape.

🎮 Manipule-le

Insert une value et regarde le chemin des comparisons. Puis essaie le bouton 😈 pour voir le tree dégénérer…

💡 Comment ça marche ?

Chaque node a au plus deux children, avec la règle left < node < right. La search devient une dichotomie naturelle : O(log n) si le tree est balanced.

  • Inséré dans l'ordre (1, 2, 3…), il degenerate en linked list → O(n).
  • D'où les self-balancing trees (AVL, red-black) utilisés par les standard libraries.

⏱️ Complexity

Search (balanced)O(log n)
Insert (balanced)O(log n)
Delete (balanced)O(log n)
Worst case (degenerate)O(n)

💼 Là où tu le croises en vrai

🗄️ Database indexesLes index SQL sont des B-trees, la généralisation du BST.
📚 Sorted mapsTreeMap (Java), std::map (C++) = red-black trees.
💶 Range search« Tous les prix entre 10 et 50 € » — impossible efficacement avec un hash.
🏆 Classements dynamiquesMaintenir un order pendant que les données bougent en permanence.
🎯 En entretien : le combo gagnant tient en deux phrases — « in-order traversal = sorted values » et « balanced O(log n), degenerate O(n), d'où AVL / red-black ». Ces deux phrases répondent à 80 % des questions sur les BST.

🗂️ La hash table

La structure « annuaire » : une hash function transforme la key en numéro de case, et on y va directement. Search, insert, delete : O(1) en moyenne.

🎮 Manipule-la (8 buckets)

Insert plusieurs keys : quand deux tombent dans le même bucket, c'est une collision → chaining.

💡 Comment ça marche ?

h(key) → index dans un array de buckets. Deux keys peuvent tomber dans le même bucket : c'est une collision, gérée par chaining (list dans le bucket) ou open addressing.

  • Trop remplie ? On agrandit et on rehash tout.
  • Contrepartie : aucun order — impossible de demander « les keys entre A et C ».

⏱️ Complexity

SearchO(1) moyen
InsertO(1) moyen
DeleteO(1) moyen
Worst case (collisions massives)O(n)

💼 Là où tu la croises en vrai

🧰 Les objets de ton langage{} en JS, dict en Python, HashMap en Java.
⚡ Caches & sessionsRedis, Memcached, sessions utilisateur, memoization.
🔁 Deduplication & comptageSet, compter des fréquences en un seul passage.
🧭 Routing & indexTables de routing, index inversé d'un moteur de recherche.
🎯 En entretien : réflexe — « il faut que ce soit rapide » → hash map. Two Sum, anagrammes, détection de doublons : O(n) avec une map. Bonus : explique les collisions et pourquoi le worst case est O(n).

🧭 Quelle structure pour quel besoin ?

Access par position / parcours rapide→ 🧮 Array
Insertions fréquentes au head, undo/redo, LRU→ 🔗 Linked list
Revenir en arrière, DFS, parenthèses, call stack→ 🥞 Stack
Traiter dans l'ordre d'arrivée, BFS, message queues→ 🚶 Queue
Données sorted, range search, min/max→ 🌳 BST (balanced)
Association key → value, doublons, comptage→ 🗂️ Hash map
Toujours sortir le plus prioritaire→ ⛰️ Heap (priority queue)
Relations entre entités, réseaux, chemins→ 🕸️ Graph (BFS/DFS)
🎯 La phrase magique en entretien : « Je choisis X parce que l'opération dominante ici est Y, et X la fait en O(…) ». Structure + opération dominante + complexity : c'est exactement le raisonnement attendu.
