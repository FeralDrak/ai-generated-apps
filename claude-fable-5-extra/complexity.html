Les 7 classes de complexité à connaître

La notation Big-O décrit comment le temps (ou la mémoire) d'un algorithme grandit quand la taille des données n grandit. Clique sur une carte pour ouvrir la fiche complète — avec analogie, code et la phrase à sortir en entretien.

🏅 Les 6 règles d'or pour évaluer une complexité

1
On garde le terme dominant

O(n² + n + 40) = O(n²). Quand n devient grand, seul le terme qui croît le plus vite compte.

2
Les constantes disparaissent

O(3n) = O(n). Parcourir un tableau 3 fois reste linéaire — Big-O décrit la forme de la croissance, pas la vitesse exacte.

3
Boucles imbriquées → on multiplie

Une boucle de n tours contenant une boucle de n tours = n × n = O(n²).

4
Boucles successives → on additionne

Deux boucles l'une après l'autre = n + n = O(n). L'addition ne change pas la classe, la multiplication si.

5
Diviser par 2 à chaque étape → log n

Recherche binaire, arbres équilibrés… Dès qu'on coupe le problème en deux, on entend « logarithme ».

6
Méfie-toi des coûts cachés

includes, slice, unshift, str +=… Une seule ligne peut cacher un O(n) entier. Un O(n) caché dans une boucle = O(n²).

🪤 Les coûts cachés de JavaScript

  • arr.includes(x), indexOf, find → O(n) — dans une boucle, ça devient O(n²) !
  • arr.slice(), [...arr], concat → O(n) — chaque copie parcourt tout.
  • arr.unshift(x), splice → O(n) — tout le tableau est décalé.
  • arr.push(x), pop() → O(1) amorti — les seuls « gratuits ».
  • arr.sort() → O(n log n) — souvent le terme dominant d'une solution.
  • str += mot en boucle → O(n²) — les chaînes sont immuables, chaque += recopie. Préfère parts.push(...) puis join("").
  • map.get(k), set.has(x) → O(1) en moyenne — l'arme secrète pour passer de O(n²) à O(n).

💬 Les phrases qui font mouche en entretien

  • « Je commence par la solution naïve en O(n²), puis je l'optimise — souvent avec une hash map pour descendre en O(n). »
  • « Une hash map, c'est échanger de la mémoire contre du temps : recherche O(n) → O(1). »
  • « Le tableau est trié ? Ça sent la recherche binaire ou les deux pointeurs. »
  • « Ma solution est en O(n log n) en temps à cause du tri, et O(n) en espace pour la copie. » (toujours donner temps ET espace)
  • « Le pire cas du quicksort est O(n²), mais en pratique le pivot aléatoire le rend O(n log n). »
  • « En dessous de n ≈ 10⁸ opérations, ça tient en une seconde — donc O(n²) passe pour n ≤ 10 000 environ. »
